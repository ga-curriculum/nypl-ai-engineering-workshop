# Module 4: Transparency and Governance

## Overview

| Detail | Info |
|---|---|
| **Duration** | 30 minutes (20 min lecture + 10 min Lab 4) |
| **Position** | 2:30–3:00 PM |
| **Tools** | Discussion-based (minimal tool use) |
| **Lab** | Lab 4: Code Review Tagging |

## Learning Objectives

By the end of this module, participants will be able to:
1. Articulate when and how to disclose AI-assisted code in PRs
2. Identify IP and licensing considerations for AI-generated code
3. Apply a code review tagging system to distinguish AI-generated from human-written code
4. Describe what an organizational AI governance policy should include

## Content Outline

### Part 1: Transparency in Practice (10 min)
- When should you disclose AI assistance? (PRs, documentation, code comments)
- What does your team need to know about how code was generated?
- The spectrum: fully AI-generated → AI-assisted → AI-reviewed → human-only
- Quick poll: What's your team's current practice?

### Part 2: Governance and Guardrails (10 min)
- IP considerations: Who owns AI-generated code?
- License compliance: What training data concerns exist?
- Organizational policies: What should an AI coding policy cover?
- The QA framework as governance: structured review as risk mitigation

### Part 3: Lab 4 — Code Review Tagging (10 min)
- Label code samples as AI-generated, AI-assisted, or human-written
- Apply the security auditor persona as a governance check
- See [labs/lab-4-code-review-tagging/](../../labs/lab-4-code-review-tagging/)

## Notes

This is intentionally the lightest module. The goal is discussion and awareness, not deep technical content. Use it as a bridge to the capstone, where participants apply everything they've learned.
